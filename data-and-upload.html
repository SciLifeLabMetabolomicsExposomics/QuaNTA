Your data and its processing (page 1)

Page 1 of the app, Input data and processing, is where everything starts: you describe the project, upload the MS-DIAL file, read it and process it. This chapter shows how the file must be structured, what QuaNTA checks when it reads it, and what the processing settings do.

The data file

QuaNTA reads the alignment result exported from MS-DIAL (Export → Alignment result, peak areas) as a tab-delimited .txt file. Upload it as it is, or compressed as .zip or .gz with that one file inside.

The file has two parts: four rows of sample information at the top, and below them one row per feature (a compound or an unknown peak) with its peak area in every sample. This is the top-left corner of the example file:

File type Blank Standard Standard Standard
Injection order 1 2 3 4
Batch ID 1 1 1 1
Alignment ID Average Rt(min) Average Mz Metabolite name Comment MS/MS spectrum PROCBLK3_B1_1 Cal0_E_B1_2 Cal0-005_E_B1_3 Cal0-01_E_B1_4
16572 13.016 219.17401 (+)-Nootkatone Quant 2698760 0 419457 749115
5569 9.437 136.02139 1,3-benzothiazole Quant 2713850 131522 0 0

15351 7.449 212.11803 1,3-Diphenylguanidine Quant 100897380 1928345 2064414 2317076

The four sample rows (shaded) describe each sample column:

Row Content In QuaNTA
Class the group of the sample, e.g. Healthy, QC1, C0-5 the groups in figures and statistics
File type Sample, QC, Standard or Blank study sample, QC, calibration sample or (method) blank
Injection order a number the order along the run (drift, figures over the sequence)
Batch ID a number blank subtraction and calibration per batch

The feature columns QuaNTA needs (exact names): Alignment ID, Average Rt(min), Average Mz, Metabolite name and Comment. Other columns are ignored.

Naming conventions

The Comment column tells QuaNTA what each feature is:

Comment Meaning
Quant a targeted compound, quantified with a calibration curve
Quant\<class> a targeted compound with a compound class after the backslash, e.g. Quant\ATZ
IS an isotope-labelled internal standard
IS\<class> an internal standard with a compound class, e.g. IS\ATZ
vIS the volumetric internal standard (added to check and correct the volume)
R removed from the data when it is read
empty or anything else a non-targeted feature

The calibration samples (File type = Standard) carry their concentration in the sample name, after Cal, with a dash for the decimal point: Cal0 (the zero calibrant), Cal0-005 (0.005), Cal0-5 (0.5), Cal10 (10). QC samples with the same Class are replicates of one QC material; several QC materials (e.g. QC-low, QC-high) are possible.

The example file has 196 targeted compounds, 22 internal standards, 1 volumetric internal standard and 1000 non-targeted features, measured in 299 samples in 3 batches.

WarningCheck before uploading

When you click Process data, QuaNTA lists Comment values that do not follow the conventions (e.g. quant, IS-ATZ) and column names that look like the required ones but are not exact (e.g. Comment2). Values that look like Quant or IS are shown in red: they would be treated as non-targeted. Fix them in MS-DIAL or in the file and upload again.

Uploading and reading

  1. Fill in the project information (title, user, unit of the concentrations). It goes into the reports.
  2. Optionally load a parameters file (.yml) saved earlier with Download settings; the example has example_data/QuaNTA_example_parameters.yml. Loading one replaces all settings and removes the results of a previous run (QuaNTA asks first).
  3. Upload the data file and click Read data file. The Data reading log on the right shows what was read; page 2 then shows an overview of the data.

Processing settings

The settings are grouped as in the app. Hover the ⓘ next to each in the app for the full explanation; options that the data cannot support (e.g. a volumetric IS option without a vIS) are greyed out.

Click Process data to run all steps. Before it starts, a popup lists anything worth checking: settings that were corrected (e.g. a number outside its range), Comment values and column names that do not follow the conventions, and notes on the data (e.g. no targeted compounds, or batches that will use the global calibration curve). The Processing log shows the progress; when it is done, pages 3 and 4 show the results.

TipSave your settings

Download settings (.yml) saves the project information and all settings, with the name of the dataset. Load the file later to process the same way, or use it with the command-line version (run_quanta.R).
